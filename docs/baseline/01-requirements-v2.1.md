## 1. 背景与问题陈述

### 1.1 项目背景

> 本节及第 2 节所述内容为**背景信息与调研事实**，用于解释需求的由来，本身不构成需求条款。需求条款见第 3 节起。

休闲消除类游戏（如 Candy Crush、开心消消乐）长期占据休闲游戏市场主流。其核心吸引力在于：单局时长短（1–5 分钟）、规则上手快、进度反馈强，适合碎片时间游玩。但主流产品普遍存在安装包体积大、强制社交与广告干扰、对低配设备不友好等问题。

本项目拟开发一款**免安装、纯浏览器运行**的轻量级关卡制三消网页游戏《星消乐》（暂定名）：玩家在浏览器中直接游玩，核心玩法为"交换相邻元素使三个及以上同色元素连成一线即可消除"，包含关卡进度、积分与排行榜、音效与动画反馈。

**事实性背景（已核实，核实过程见《03-人工核实说明》V-01、V-02）：**

| 编号 | 背景事实                                                                                   | 来源                                                                     |
| ---- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| B-1  | 《开心消消乐》《糖果传奇》等消除类产品长期位于移动端休闲游戏活跃榜前列，该品类需求持续存在 | 应用商店与 TapTap 中国区休闲榜公开排名；厂商官网玩法说明（2026-09 查询） |
| B-2  | 主流三消产品的经典关卡结构（限步数 + 目标分数 + 1~3 星评价）已被市场长期验证               | 同上                                                                     |
| B-3  | 主流产品的体力（生命）恢复周期普遍落在 15–30 分钟区间                                     | 开心消消乐、Royal Match 公开资料                                         |

### 1.2 问题陈述

当前问题：休闲玩家在 PC 浏览器场景下缺少一款**即开即玩、无安装、无强制社交**的消除类游戏；现有页游普遍广告干扰严重、离线后进度丢失。

> **问题陈述（Problem Statement）：** 为碎片时间休闲玩家提供一款在主流浏览器中免安装运行、进度可持久保存、具备完整"关卡—积分—排行榜"反馈闭环的轻量级三消网页游戏。

## 3. 功能需求

**优先级定义：**

- **H（高）**：首版必须实现，缺失则产品不成立；
- **M（中）**：首版应实现，显著提升体验；
- **L（低）**：可延后至后续版本。

每项需求含编号、描述、优先级、验收标准（AC）与来源编号（SRC，见第 8.1 节）。AC 均为可执行、可判定表述；对应的验收用例编号见第 8.2 节追溯矩阵与附录 C。

### 3.6 数据格式与接口

**3.6.1 本地存档（localStorage，键名 `gemz_save_v1`，JSON，UTF-8）**

```json
{
  "version": 1,
  "unlockedLevel": 13,
  "stars": { "1": 3, "2": 2 },
  "bestScores": { "1": 4500 },
  "totalScore": 18600,
  "coins": 320,
  "items": { "shuffle": 2, "hammer": 1, "plus5": 0 },
  "lives": 4,
  "livesUpdatedAt": "2026-09-14T10:30:00+08:00",
  "livesRestored": 2,
  "muted": false,
  "colorblind": false,
  "nickname": "星消乐玩家",
  "rewardPaidStars": { "12": 3 },
  "updatedAt": "2026-09-21T21:14:00+08:00"
}
```

字段说明：`version` 为存档结构版本号（供 FR-15 迁移使用）；`stars`、`bestScores` 以关卡号为键；`totalScore` 为各关最高分之和（FR-17）；`livesUpdatedAt` 为生命恢复计时锚点，`livesRestored` 为自该锚点起已计入的恢复次数（FR-14、FM-07）；`muted`、`colorblind` 为设置项持久化（FR-26、FR-30）；`nickname` 为排行榜昵称（FR-19）；`rewardPaidStars` 记录各关已发放金币奖励的最高星级，用于 FR-23 的差额补发与折半判定；`updatedAt` 为存档最后写入时间戳，用于 FM-13 的多标签页写入冲突判定。

**3.6.2 排行榜提交接口**

- 接口：`POST /api/score`，`Content-Type: application/json`
- 请求体：`{ "nickname": "string 3-12", "totalScore": "int >= 0" }`
- 成功响应：`{ "code": 0, "rank": 5 }`
- 错误响应：`{ "code": 1001 | 1002 | 5000, "msg": "string" }`

| 错误码 | 含义                       | 客户端处理                                                |
| ------ | -------------------------- | --------------------------------------------------------- |
| 0      | 成功                       | 更新本地显示的名次                                        |
| 1001   | 昵称非法（长度或字符集）   | 提示"昵称仅支持 3–12 个中英文、数字或下划线"，留在设置页 |
| 1002   | 分数非法（越界或类型错误） | 提示"分数数据异常，本次成绩未提交"，不影响单机进度        |
| 5000   | 服务端错误                 | 提示"排行榜暂时不可用"，提供重试按钮；单机游玩不受影响    |

**3.6.3 排行榜查询接口**

- 接口：`GET /api/rank?limit=100`
- 成功响应：`{ "code": 0, "list": [ { "rank": 1, "nickname": "string", "totalScore": "int", "avatar": "string|null" } ] }`
- 请求超时阈值：3 秒；超时或非 0 返回码均触发 FR-20 的降级逻辑。

**3.6.4 关卡配置（`levels.json`，构建期静态资源）**

关卡数值以 JSON 配置驱动（NFR-10），字段定义如下，启动时按 FM-12 逐条校验。

```json
{
  "version": 1,
  "levels": [
    {
      "level": 16,
      "segment": 3,
      "rows": 8,
      "cols": 8,
      "colors": 5,
      "moves": 25,
      "goals": {
        "score": 1900,
        "collect": { "color": 2, "count": 14 },
        "ice": { "total": 7, "doubleRatio": 0.15 }
      },
      "starKeep": { "keep2": 6, "keep3": 11 }
    }
  ]
}
```

| 字段 | 类型 | 取值范围 | 校验规则（FM-12） |
| ---- | ---- | -------- | ----------------- |
| `version` | int | ≥ 1 | 缺失或 < 1 时整份配置视为非法，回落为内置默认配置 |
| `levels[].level` | int | 1–30 | 越界或重复 → 该条非法 |
| `levels[].segment` | int | 1–3 | 与 `level` 所属分段不匹配 → 该条非法 |
| `levels[].rows` / `cols` | int | 8 | ≠ 8 → 该条非法（BR-01） |
| `levels[].colors` | int | 5 | ≠ 5 → 该条非法（BR-01） |
| `levels[].moves` | int | 16–25 | ≤ 0 或 > 25 → 该条非法 |
| `levels[].goals.score` | int | 1000–2740 | ≤ 0 → 该条非法 |
| `levels[].goals.collect.color` | int | 0–4 | 越界 → 忽略该收集目标 |
| `levels[].goals.collect.count` | int | 10–28 | ≤ 0 → 忽略该收集目标 |
| `levels[].goals.ice.total` | int | 0–9 | < 0 或 > 64 → 该条非法 |
| `levels[].goals.ice.doubleRatio` | number | 0–1 | 越界 → 取 0（即全部为单层冰） |
| `levels[].starKeep.keep2 / keep3` | int | 0 ≤ keep2 < keep3 ≤ moves | 不满足 → 该关星级阈值按 BR-07 重新标定 |

**校验时机与粒度：** 启动时逐条校验；非法条目回落为该分段的默认配置并写入本地日志键；若合法条目不足 30 条，则整体判定自检失败，提示"关卡数据异常"（FM-12）。

### 4.2 优先级分布与依据

功能需求 32 项（FR-01~FR-32）的优先级分布如下。

| 优先级 | 需求项数 | 占比 | 对应的使用频率特征                                                                                                                                                       |
| :----: | :------: | :--: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
|   H   |    14    | 43.75% | 每一局都会触及的必经路径：棋盘生成、交换与回弹、消除与连锁、死局处理、关卡目标、关卡失败判定、结算与星级、关卡解锁、进度保存、得分构成、无付费约束、动画、音效与静音、结算弹窗信息     |
|   M   |    15    | 46.875% | 多数玩家在若干局内会触及：连锁提示、特殊元素、局内星级预告、生命值、存档兼容、排行榜相关（总积分、榜单、昵称、降级、一致性）、道具与经济、后台暂停、响应式布局、新手引导 |
|   L   |    3    | 9.375% | 少数玩家使用或面向特定人群：存档导入导出、键盘可达性、色盲友好模式（后两者面向无障碍人群，实现成本低故保留在首发范围）                                                   |

优先级与使用频率总体正相关：H 项均为单局内的必经操作，缺失即导致产品不成立；M 项为提升体验的增强项；L 项为可选功能或面向特定人群的功能。

**关于 M 与 H 的边界判定：** FR-14（生命值）与 FR-22（道具）置于 M 而非 H，理由是二者并非单局必经路径——生命值为 0 时仅限制新开一局，玩家仍可重玩已解锁关卡或按 FR-14 的 15 分钟周期等待恢复，缺失该机制时核心玩法仍完整；道具是提升通关率的可选手段，不使用道具也能按 BR-05 的通过率目标通关。二者均不满足 H 级"缺失则产品不成立"的定义，但触发频率高于 L 级功能，故定为 M。

非功能需求 14 项（NFR-01~NFR-14）中 H 级 7 项（性能、兼容性、可靠性、安全、架构约束、可恢复性）、M 级 6 项、L 级 1 项，H 级集中在"能不能用、会不会丢数据"这类底线指标上。

### 7.3 难度验证与递增判据

| 编号  | 规则                                                                                                                                                                                       |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| BR-05 | **难度验收规则：** 每关用普通玩家代理求解器（逻辑见附录 B）随机模拟 **200 次**，单关合格判据为通过率的 **Wilson 95% 置信区间下限 ≥ 60%**（不以点值判定）；难度总体递增以"三段平均通过率依次递减"为判据。**逐关通过率目标区间：第 1 段（关 1–5）≥ 95%、第 2 段（关 6–15）≥ 90%、第 3 段（关 16–30）60%~85%；三段目标均值依次为 98% / 96% / 74%**，需求阶段按此目标标定各关数值（V-13）。 |

## 10. 术语表

| 术语             | 定义                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| 三消             | 交换相邻元素，使三个及以上同色元素横或竖连成一线并消除的玩法                                        |
| 连锁（cascade）  | 一次消除后元素下落形成的新消除，可连续触发                                                          |
| 死局             | 当前棋盘不存在任何能形成三连的相邻交换                                                              |
| 特殊元素         | 4 连或 5 连以上消除时生成的炸弹 / 彩虹元素                                                          |
| 冰层             | 覆盖在格子上的障碍层，不阻止交换；该格元素被消除时冰层减 1 层，减到 0 即破坏并计入冰层目标（FR-07） |
| 覆盖层模型       | 障碍附着于"格子位置"而非"元素"，元素被消除后新落下的元素仍受该格冰层覆盖                            |
| 星级             | 依据结算时剩余步数评定的 1–3 星评价（BR-07）                                                       |
| 通关余步         | 达成全部目标时剩余的步数                                                                            |
| 代理求解器       | 测试用贪心策略求解器：只看一步直接收益并追踪未完成目标，用于量化关卡可解性与难度                    |
| 降级             | 依赖不可用时退化为功能受限但可用的状态（如排行榜退化为本地模拟榜单）                                |
| 第一屏可交互时间 | 页面加载到玩家可进行首次有效操作的时间                                                              |
| 连锁次数上限 | 单步最多可触发的连锁次数，取 8；据此得出连锁系数上限 4.5（NFR-08 的 S_max 推导依据） |
| Wilson 置信区间 | 小样本比例（通过率、达标率）的区间估计方法；本项目以区间下限判定是否达标，避免小样本点值失真（BR-05、BR-07） |
| 奖励已发放星级 | 各关已按最高星级发放过金币奖励的记录（`rewardPaidStars` 字段），用于 FR-23 的差额补发与折半判定 |
| 标签页写入冲突 | 同一浏览器多标签页并发写入同一份存档导致的相互覆盖（FM-13） |

## 附录 B 关卡难度与星级标定的验证方法（伪代码）

**B.1 普通玩家代理求解器**

```
输入：关卡配置 cfg（步数 M、目标 T/C/I、冰层布置）
输出：是否通关、完成时剩余步数、通关样本得分

for trial in 1..200:
    board = 生成棋盘(保证有解)
    movesLeft = M
    while movesLeft > 0 and 目标未全部达成:
        候选 = 枚举所有相邻交换(约 112 组)
        best = 对每个候选执行交换后，按
               [直接消除的元素数 × 10
                + 连锁预期收益
                + 对未完成目标的加权贡献
                + 特殊元素触发收益] 打分，取最高者
        if best 的得分 <= 0: 随机交换一组  # 模拟玩家随意乱点
        执行 best；movesLeft -= 1；结算连锁
    记录(是否通关, 剩余步数, 得分)
```

**B.2 星级阈值标定**

```
对每一关：
    收集该关全部通关样本的"完成时剩余步数"序列 S
    keep3(n) = 分位数(S, 0.70)
    keep2(n) = 分位数(S, 0.35)
验收：
    计算通过率的 Wilson 95% 置信区间 [lo, hi]（样本量 n = 200）
    逐关 lo >= 60%                      # 以置信区间下限判定，不用点值
    三段平均通过率依次递减
    星级分布有区分度：1★ <= 50%、2★ >= 25%、3★ >= 5%
    最不利关卡的 2★ 达标率 >= 45%
```
