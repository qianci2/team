## 3. 关键口径（实现时必须沿用）

1. **K-03 算术修正**：`01` 中“总积分硬上限 =（90+180+347）×3480 = 2,147,160”有笔误。段 3 步数合计为 **345**，`ΣM(n) = 615`，硬上限应为 **`615 × 3480 = 2,140,200`**；服务端拒绝阈值仍是 **2,150,000**，TC-38 判定值不变。设计文档已全部改用 2,140,200。
2. **K-01 冰层行权重**：`[12,12,12,10,8,6,4,0]`。
3. **K-02 生命锚点推进算法**、**K-04 存档 `version` 递增策略**：见设计正文 §13.2。
4. **星级阈值 `starKeep`**：设计文档 §7.3.2 给出 30 关预置值，并明确标注“待代理求解器 200 次/关标定后回写”。这些是待标定值，不得当成实测结论。
5. **无代码声明**：基线中的 `levels.json`、接口、模块、表结构都是设计定义，不是仓库中已存在的实现。README 与文档不得声称已实现。

## 4. 变更规则

- 需求编号与语义不改；确需修改时，新增 `K-05` 起的记录，写清：改了哪些、为什么、影响哪些需求、对验收判据的影响。
- 同步更新设计文档的追溯矩阵与受影响接口/数据/流程。
- 代码与测试引用需求编号；PR 模板要求填写关联编号。
- 不允许“悄悄改”：评审时若发现实现与基线不一致，要么改实现，要么补变更记录。
